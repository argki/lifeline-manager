# ライフライン使用量・料金管理アプリ 要件定義書

## 1. 背景と目的

### 1.1 現状の課題（As-Is）
現在、水道・電力・ガスなどのライフラインの使用量と料金を Excel（永続版）＋ VBA マクロで管理しているが、以下の課題を抱えている。

1. **Excel / VBA 依存リスク**
   - 永続版 Excel を利用しているため、将来的な Microsoft のサポート終了リスクがある。
   - VBA マクロの保守・動作保証に継続的なリスクが伴う。
2. **運用の煩雑さ（手動反映・年次メンテナンス）**
   - 原本シート（1年あたり「使用量」「金額」の2行構成）からグラフ用隠しシート（`*_Hide`）へデータを転記するマクロを、毎回「グラフに反映」ボタンで手動実行する必要がある。
   - あらかじめ用意した最終年（例：R10、R14）に達すると、手動で行・和暦・数式・グラフ参照範囲を追加修正するメンテナンスが発生する。
   - 未入力の将来年において、平均列に `#DIV/0!` エラーが表示されている。
3. **クロスプラットフォーム対応と環境汚染の回避**
   - Windows と macOS の双方で安定して動作確認・利用できる環境が求められている。
   - 開発ツールや依存ライブラリを PC 本体に直接インストールして環境を汚さず、かつユーザーは複雑なコマンド操作なしで手軽に起動したい。
4. **複数拠点の管理**
   - ライフラインを管理する拠点が複数存在するため、1つのアプリ内で拠点を切り替えて一元管理したい。

### 1.2 目的（To-Be）
- Excel / VBA から脱却し、**Windows / macOS 両対応のローカル起動型 Web アプリケーション**として再構築する。
- **複数拠点**（例：自宅・実家・別拠点など）を同じアプリ内でシームレスに切り替えて管理できるようにする。
- これまで Excel で実現していた入力・集計・グラフ比較の体験を維持しつつ、**入力即グラフ反映**や**年次の自動・簡単追加**により運用負荷をなくす。
- **コンテナ管理（Docker 等）**により開発環境・ユーザー環境を汚さない構成としつつ、ユーザーは**起動ファイルをダブルクリックするだけ**でブラウザ起動まで完了できる体験を提供する。
- データは外部へ送信せず**完全ローカル環境内に保存**し、セキュリティ・プライバシーを確保する。
- **モダン・AI が扱いやすい・人間が保守しやすい・依存モジュールを常に最新に保てる**技術構成を採用する。

## 2. 対象種別の仕様整理

本アプリで管理するライフライン種別の基本仕様は以下の通り。
（※「灯油」は対象外）

| 項目 | 水道 | 電力 | ガス |
| :--- | :--- | :--- | :--- |
| **使用量単位** | `㎥`（整数） | `kWh`（小数点第1位） | `㎥`（小数点第1位） |
| **金額単位** | `円`（整数・カンマ区切り） | `円`（整数・カンマ区切り） | `円`（整数・カンマ区切り） |
| **請求サイクル** | **隔月**（1, 3, 5, 7, 9, 11月） | **毎月**（1〜12月） | **毎月**（1〜12月） |
| **月表記の補足** | 上段に「請求月」表記 | 「2月請求」〜「1月請求」等、利用月と請求月の対応を併記 | 1月〜12月 |
| **年次表記** | 和暦（H17〜H31, R2〜） | 和暦（H29〜H31, R2〜） | 和暦（H29〜H31, R2〜） |
| **年次集計** | 合計・平均 | 計・平均 | 計・平均 |
| **グラフ** | 平成（H29〜H30）と令和（H31〜）の2つに分けた使用量の月別推移折れ線グラフ | 同左 | 同左 |

## 3. 機能要件

### 3.1 拠点・ライフライン種別管理
- **F-00: 複数拠点の管理・切り替え**
  - ヘッダーまたはサイドバー等から、管理対象の**拠点**（例：拠点A、拠点B 等、任意の名称）をワンクリックで切り替えられること。
  - 拠点の新規追加・名称変更・並び替え（または削除時の誤操作防止確認）ができること。
  - 拠点の追加・名称変更・削除といった管理操作は日常的には使用しないため、**デフォルトでは折りたたみ（またはメニュー格納）等で非表示**とし、必要時のみ展開して操作できること（普段は拠点切り替え UI のみを表示し画面をすっきりさせる）。
  - 拠点ごとに「水道」「電力」「ガス」のデータおよび種別メタデータ（事業者名、単位、請求サイクル等）を独立して保持できること。
- **F-01: 種別ごとの管理画面**
  - 選択中の拠点配下で、**対象種別「水道」「電力」「ガス」の3種類**をタブ等で切り替えて管理できること。（「灯油」は運用終了のため対象外）
  - 種別ごとに以下のメタデータを設定・保持できること（拠点ごとの契約形態の違いや将来の変更に対応するため）。
    - 使用量の単位（例：`㎥`, `kWh`）および表示小数点桁数
    - 対象月パターン（毎月 1〜12月 / 隔月 1,3,5,7,9,11月）
    - 請求月ラベルの補足表示（例：1月利用＝2月請求）
  - 画面上の表見出しには「東京電力」「プロパンガス」「水道使用量」といった特定事業者・契約形態に限定した名称は表示しないこと（上部の「水道」「電力」「ガス」タブにより選択中の種別が明確であるため）。
  - **種別ごとのテーマカラー統一と視認性配慮**:
    - 選択中の種別に応じて、タブ・主要アクション・フォーカス枠・表の金額行背景色（ティント）などの UI テーマカラーを種別ごとに統一すること。
    - **水道**: 青系で統一する。
    - **電力**: 雷をイメージした黄色系（イエロー／アンバー系）で統一する。
    - **ガス**: 炎をイメージした紫系（パープル系）で統一する。
    - すべての種別において、文字・アイコン・罫線・ボタンラベル等のコントラスト比（視認性・可読性）に配慮し、特に黄色系でも白背景上やボタン内で視認性が低下しない配色とすること。

### 3.2 データ入力・一覧表示
- **F-02: 表形式での直感的な入力・編集と Undo / Redo**
  - 現行 Excel と同様、**年（行）× 月（列）** のマトリクス形式で一覧表示し、セルを直接クリック・キーボード操作で「使用量」「金額」を入力・編集できること。
  - 1年につき上段「使用量」、下段「金額」の2段表示を維持し、視認性を保つこと。
  - **スクロール時の年・月固定表示**: 表を縦・横にスクロールした際も、月ヘッダ行（上部）および年列（左端）が固定表示（Sticky）され、どの年・月のセルを操作しているか常に把握できること。
  - **実用的な Tab / キーボード遷移順序**:
    - 表内の `Tab`（および `Shift+Tab`）遷移は HTML テーブルの行順ではなく、実務の入力フローに沿った論理順序（**各月の「使用量」→ 同月の「金額（円）」→ 翌月の「使用量」→ … → 最終月の「金額（円）」→ 同年の「備考」→ 翌年の最初の月の「使用量」**）で移動すること（`Shift+Tab` は完全な逆順）。
    - 最終年の「備考」から `Tab` を押した場合は表最下部の「年を追加（`+`）」ボタンへ遷移し、表の入力完了後にそのまま次の年を追加しやすくすること。
    - 数値セルで `Enter` キーを押した際も確定だけで終わらず、次の入力セル（同月の金額、または次の入力対象）へ移動できるようにし、Excel に近い連続入力体験を提供すること。
    - 備考欄（テキストエリア）内での `Tab` / `Shift+Tab` も同様に論理順序で前後セルへ遷移すること（改行は `Enter`）。
  - **元に戻す（Undo）／やり直す（Redo）**: `Ctrl+Z` / `Ctrl+Y`（macOS では `Cmd+Z` / `Cmd+Shift+Z` も対応）のキーボードショートカットおよび画面上の「元に戻す」「やり直す」ボタンにより、セル編集や年の追加・削除を取り消し／再実行できること（ローカル保存データとも同期）。
- **F-03: 年次の柔軟な追加・削除（メンテナンスフリー化と誤操作防止）**
  - あらかじめ空の将来年を大量に用意しておく運用を廃止し、表の**「年」列の最下部**に配置したプラス（`+`）ボタンで次の年（末尾の翌年）をワンクリックで追加できること（年を飛ばして追加する運用は不要なため、年指定用のテキストボックスは設けない）。
  - 同じく表の**「年」列の最下部**にマイナス（`-`）ボタンを配置し、誤って複数年を追加してしまった場合などに末尾の年を削除できること。
  - `+` / `-` ボタンのみでは操作対象が分かりにくいため、マウスホバー時に対象年や操作内容を示す文字（例：`2027 (R9) 年を追加` / `2026 (R8) 年を削除`）をツールチップ表示すること。
  - 誤削除を防ぐため、**削除対象年の明示・入力済みデータ件数を含む確認ダイアログ**および **Undo（元に戻す）による復元**を備えること。
  - 内部的には西暦（例：`2026`）でデータを保持し、表示上は和暦（例：`R8` / `2026 (R8)`）へ自動変換することで、元号変更や年数増加に強い構造とすること。

### 3.3 自動集計
- **F-04: 合計・平均のリアルタイム算出**
  - 各年の「合計」「平均」を、使用量・金額それぞれについて入力と同時に自動計算して表示すること。
  - **エラー表示の排除**: 実績が入力されていない月（空欄）は平均の分母から除外し、実績が0件の年は `#DIV/0!` ではなく `-` 等で表示すること。
  - 途中年（例：H29 の 10〜12月のみ入力、最新年の途中月まで入力）でも、入力済み月数のみで正しく平均を算出すること。

### 3.4 グラフ可視化（VBA 廃止・リアルタイム反映）
- **F-05: 入力即反映の月別推移グラフ**
  - 従来の「グラフに反映」ボタンおよび隠しシート生成マクロを廃止し、**表の値を変更した瞬間にグラフへ自動反映**されること。
- **F-06: 年別比較の折れ線グラフ**
  - 選択中の拠点・種別について、縦軸を**使用量**、横軸を月（1〜12月、隔月の場合は対象月）とし、年ごとの折れ線グラフを重ねて比較できること。
  - **表示年の柔軟なフィルタリング（単一グラフ統合）**:
    - 現行 Excel のように平成・令和でグラフを2つに分割せず、**1つの折れ線グラフに統合**して表示すること。
    - 比較したい年をチェックボックス等で自由に ON/OFF できること。
    - 新しい年が追加されても、グラフの参照範囲を手動修正することなく自動で凡例・系列に追加されること。
  - マウスホバーで該当月・年の正確な数値（使用量・金額）をツールチップ表示できること。
  - ツールチップ内に表示される各年の数値は、該当月の**値が大きい順（降順）**に並べて表示すること。
  - *（将来拡張・優先度低）*: 同じ画面上でグラフの表示対象を「使用量」から「金額」へ切り替えられる機能（データ構造としては金額も保持し、拡張可能な設計とする）。

### 3.5 データ保存・移行（インポート／エクスポート）
- **F-07: ローカルデータ永続化とバックアップ**
  - セキュリティ重視のため、データはクラウドや外部サーバーへ送信せず、**ローカル PC 内（ホスト側ディレクトリのボリュームマウント先）に保存**し、コンテナの再作成・アプリ終了後も保持されること。
  - バックアップや PC 間移行用途として、全拠点一括または拠点単位で JSON / CSV 形式のエクスポート／インポートができること。
  - データ移行・バックアップに関する操作 UI（CSV インポート、JSON / CSV エクスポート・インポート）は日常的には使用しないため、**デフォルトでは折りたたみ等で非表示**とし、必要時のみ展開して操作できること。
- **F-08: 既存 Excel / CSV データの移行**
  - 既存の Excel から書き出した CSV ファイルから過去実績（H17〜現在）を指定した拠点へ取り込める手段を用意すること。
  - 取り込み時は以下の実データ特性を吸収できること：
    - 月ヘッダ行の位置ゆらぎ（2行目または3行目）を自動検出し、`計` / `平均` 列や表外のメモ列を無視すること。
    - 全角/半角文字（例：`ｋWh`）、数値前後の空白・カンマ区切り（例：`" 5,707 "`）、和暦未入力行、および未入力年の `#DIV/0!` や `-` を適切に正規化・除外すること。
    - 使用量と金額の片方のみ入力されている月（例：使用量のみあり・金額空欄）も許容して取り込むこと。

### 3.6 複数ウィンドウ・タブ間のリアルタイム同期
- **F-09: 複数起動（複数ウィンドウ・タブ）時のリアルタイム同期**
  - 同一ローカルサーバーに対して複数のブラウザタブやウィンドウ（PWA ウィンドウを含む）を同時に起動している状態で、片方の画面でセル編集、年の追加・削除、拠点の追加・名称変更・削除、インポート等を行った際、**もう片方の画面にも手動リロードなしでリアルタイムに反映されること**。
  - **実現方式**: サーバー側でデータ更新を配信する **Server-Sent Events（SSE）**（例：`GET /api/events`）等を採用し、同一ブラウザ内の別タブだけでなく異なるブラウザ間や PWA ウィンドウ間でも `127.0.0.1` 内で完結して同期できること。
  - **画面表示状態の独立性**: 複数ウィンドウで別々の拠点・種別を並べて確認・編集できるよう、表示中の拠点・種別タブ・グラフ表示フィルタ等の表示状態は各ウィンドウ単位で独立して保持し、他ウィンドウの操作によって表示拠点が勝手に切り替わらないこと。
  - **編集中の保護・再接続**:
    - 送信元ウィンドウ識別子（`clientId` 等）により、自分自身の保存操作に伴う通知での不要な再描画・フォーカス喪失を防ぐこと。
    - 他ウィンドウからの更新を受信した際、ユーザーが現在入力中のセル（フォーカス中）がある場合は入力途中の値を壊さないよう保護すること。
    - コンテナ再起動やスリープ復帰等で接続が切れた場合は自動再接続し、最新データを再取得して同期を回復できること。
  - *（前提）*: 本アプリは単一のローカルサーバー（`127.0.0.1:3456`）に複数ウィンドウから接続する構成を前提とし、同一データファイルを別コンテナ／別プロセスから同時に直接書き換える運用は対象外とする。

## 4. 非機能要件

### 4.1 クロスプラットフォーム対応
- **NFR-01: Windows / macOS 両対応**
  - Windows および macOS の双方で同一ソースコード・同一コンテナ構成から起動し、ブラウザで動作確認・利用できること。
  - OS 固有のパス区切り文字や改行コード、フォント差異に依存しない実装とすること。

### 4.2 保守性・コンテナ管理・技術選定方針
- **NFR-02: コンテナ管理による環境非汚染とモダン技術スタック**
  - **コンテナ基盤**: **Docker / Docker Compose**（および開発用 DevContainer 対応）を採用し、Node.js ランタイムや依存ライブラリをホスト OS に直接インストールせず開発・実行できること。
  - **実行形態**: コンテナ内でローカル Web サーバーを起動し、ホスト側のブラウザから `localhost` でアクセスするローカル Web アプリケーションとする。
  - **技術スタック方針**（詳細は設計フェーズで確定）:
    - **言語**: 静的型付けにより AI のコード生成精度が高く、人間も仕様を追いやすい **TypeScript** を採用。
    - **UI フレームワーク**: エコシステムが最大級で情報量・AI 適性が高い **React**（+ Vite）を採用。
    - **ローカルデータ保存層**: コンテナ内のローカル API（Node.js 等）経由で、ホスト側からマウントしたディレクトリの JSON ファイルまたは SQLite へ永続化する構成。
    - **グラフライブラリ**: React 親和性が高い `Recharts` または `Chart.js`（`react-chartjs-2`）等を採用。
- **NFR-03: モジュールの最新化維持**
  - パッケージマネージャ（`pnpm` 等）とロックファイルにより依存関係を明確に管理すること。
  - GitHub 等で管理する場合、**Renovate** または **Dependabot** を導入し、依存パッケージのアップデート PR が自動で作成される仕組みを整えること。
  - 定期アップデート時にデグレードを防ぐため、**型チェック（`tsc`）・Linter（ESLint）・自動テスト（Vitest 等）**をコンテナ内で完結して実行・検証できること。

### 4.3 起動・操作体験（ユーザビリティ）
- **NFR-04: ダブルクリックによるワンステップ起動**
  - ユーザーがターミナルやコマンドラインを手動操作しなくても、起動スクリプトを**ダブルクリックするだけ**で以下が自動実行されること。
    1. コンテナの起動（未ビルド時・更新時は必要に応じてイメージビルド）
    2. アプリサーバーの起動待機（ヘルスチェック）
    3. OS のデフォルトブラウザでアプリ URL（`http://localhost:<port>`）を自動で開く
  - Windows 用（例：`start.bat`）および macOS 用（例：`start.command`）の起動スクリプトを提供すること。
  - 併せて、コンテナを綺麗に停止するための停止スクリプト（例：`stop.bat` / `stop.command`）も用意すること。

### 4.4 品質・テスト
- **NFR-05: ドメインロジックの単体テスト**
  - 和暦・西暦変換、隔月／毎月の集計（合計・平均計算、空欄除外）、拠点・種別ごとのデータ管理、データ移行ロジック等のコア処理には単体テストを実装し、UI と分離して保守性を高めること。

### 4.5 セキュリティ・プライバシー
- **NFR-06: 完全ローカル完結**
  - 外部ネットワークへのデータ送信や外部認証を不要とし、`127.0.0.1`（`localhost`）に限定してポート公開すること（LAN 内の他端末からのアクセスを許可しない設定）。
  - データ保存先はホスト側の指定ローカルディレクトリ（ボリュームマウント）に限定し、ユーザーがバックアップや管理を把握しやすい構成とすること。

## 5. 決定事項および実装フェーズ

### 5.1 決定事項
| 項目 | 決定内容 |
| :--- | :--- |
| **対象スコープ** | 複数拠点に対応し、同じアプリ内で拠点を切り替えて管理する |
| **対象ライフライン** | 各拠点ごとに「水道」「電力」「ガス」の 3 種別（「灯油」は運用終了のため対応不要） |
| **起動・利用形態** | コンテナ上で動作するローカル Web アプリ。ダブルクリックのみでブラウザ起動まで完結させる |
| **環境管理** | Docker / Docker Compose によるコンテナ管理（開発環境・ユーザー環境を汚さない） |
| **データ保存** | セキュリティ重視のため完全ローカル保存（ホスト側マウント領域に永続化、外部送信なし） |
| **金額グラフ** | 将来的には切り替えたいが優先度は低（Phase 2 以降で検討） |

### 5.2 実装フェーズ案
- **Phase 1（初期リリース / MVP）**
  - 複数拠点の追加・名称編集・切り替え機能
  - 各拠点における水道・電力・ガスの 3 種別タブ管理
  - 表形式での使用量・金額入力、年次の柔軟な追加、和暦/西暦表示
  - 合計・平均のリアルタイム自動計算（`#DIV/0!` 解消）
  - 入力即反映の使用量推移折れ線グラフ（平成/令和グループ表示・年別表示切替）
  - ホスト側マウント領域（JSON/SQLite 等）への永続化、バックアップ用エクスポート／インポート
  - 既存 Excel 実績データの移行機能
  - Docker / Docker Compose 環境構築、Win/Mac 用ダブルクリック起動・停止スクリプト
  - 単体テスト・Lint・型チェック・依存関係自動更新設定
- **Phase 2（将来拡張・優先度低）**
  - グラフ表示指標の「使用量」⇔「金額」切り替え機能
